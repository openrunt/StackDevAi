# Original cast conversation curriculum

This supplies original fictional conversations as training material. It is not
scripted runtime playback, a source of recorded speech timing or a trained speaker
scheduler. Dialogue fixture text is dedicated under CC0-1.0; application tooling
retains the project's AGPL-3.0 license.

There are 24 episode topics: 16 training, four validation and four test. Each has
eight authored contributions from Lyra, Orion, Nova and Kai. Four historical speaker
orders are used. Every actor contributes twice in these finite fixtures; this does
not prescribe participation frequency or order in a live response pool.

Each actor sees peers as user context and their own earlier words as assistant
history. One source record holds that actor's two contributions, and complete-reply
target extraction teaches each contribution separately. The fictional episode
premise stays in the system context. Source episodes and all four actor views stay
together in their topic's adaptation partition.

The resulting snapshot has 64 training records and 16 each for validation/test:
128/32/32 complete assistant targets. With the pinned Qwen2.5-1.5B tokenizer and
384-token context, all those targets fit without clipping; 64/16/16 retain an earlier
assistant contribution. Chat-template whitespace after the end token is preserved.
The source snapshot retains the full authored exchanges and exact corpus/source
hashes. These development holdouts are not a blind, independent preference study.

## Prepare and train

```
python -m pip install -r requirements-public.txt
python tools/prepare_cast_curriculum.py --output storage/cast-data
python tools/prepare_qwen_adapter.py --cache storage/qwen15-base
python tools/train_gguf_adapter.py --dataset storage/cast-data --base storage/qwen15-base/base.gguf --config storage/qwen15-base/tokenizer --output storage/cast-run --steps 160 --context 384 --layers 4 --target-mode all-turns --max-train-examples 128 --max-eval-examples 32
```

Use a new directory for each changed curriculum, tokenizer, training protocol or
base. An existing exact base can be reused through the preparation tool's `--gguf`
option. Base weights stay immutable. Optional preparation downloads only begin
when explicitly requested, not when opening the browser canvas.

The GGUF adapter path checks actual tokenizer/config files, selected target IDs,
source/backbone code and relevant library versions in its cache/checkpoint identity.
Selected activation storage is checked against a 512 MiB budget before allocation.
A single-writer lock prevents concurrent updates to the same output. Prefix caches
and optimizer checkpoints are saved atomically. Explicit resume uses the same options
plus `--resume` and a larger total `--steps`; it clears a prior stop request.
The original source version is required to resume a research run. Preserve older
checkpoints with their original source rather than silently migrating them.

Current and best weights, optimizer and random state share one checkpoint. A safe
stop records the final completed update even between regular evaluation intervals.
Elapsed update time continues across resumes. Prefix preparation/reuse is reported
separately, and runtime profile/rule metadata comes from the dataset manifest.

## Review the actual model

```
ollama create xputty-podcast:cast-pilot -f storage/cast-run/export/Modelfile
python export_chat.py --model storage/cast-run/export --ollama-model xputty-podcast:cast-pilot --port 8794
```

The export contains its actual native weights, portable adapter, tokenizer,
provenance, fixture source card and chat application. The native file is checked
against the named Ollama model. Select a character and supply a new topic or
challenge. Runtime words are generated by that model, not selected from the fixture.
The test chat now supports reply budgets up to 256 tokens and marks length-limited
responses; the context must also leave room for the instructions and input.

Review unseen complete exchanges for new ideas, role consistency, contradiction,
repetition and entertainment value. Lower validation loss, correct role masks and
successful export only establish parts of the pipeline. They do not establish a
usable unattended podcast, a full emotional performance or a natural voice.
